# Виправлення переліку проблем — 14 жовтня 2026

База: коміт `9e66db3`, версія 1.3.8, зі збереженням наявних незакомічених правок користувача. Роботу виконано з трьома субагентами. Версію не підвищено, комітів і публікації немає.

## Реалізовано в поточному коді

| Проблема | Зміна |
| --- | --- |
| Неповний cloud-запис після остаточного видалення | Lifecycle delta не відтворює відсутню задачу без повного запису; перевіряються merged workspace та фактичний серіалізований payload перед записом. |
| Невдале скасування видалення нотатки | Результат відновлення перевіряється, повідомлення та кнопка повтору залишаються; наступне видалення не затирає невдале Undo. |
| Дві вебвкладки блокнота | Окремі атомарні записи операцій, детерміноване відтворення та storage listener. Одночасні редакції зберігаються як дві версії, застаріле видалення не стирає новий текст. |
| Невизначені відповіді у знайомстві | Невизначена фраза з поясненням, зокрема «Ще не знаю, бо треба подумати», не закриває теми. |
| Старе питання у звичайному чаті | Продовження знайомства звіряється з останнім видимим питанням/підсумком; наявність старого pending state сама не переводить розмову у знайомство. |
| Перенесення вкладок | Єдина карта переносить поточні задачі, архів та категорії цілей. Парний журнал зберігає початковий і кінцевий workspace/profile; незавершений запис відновлюється до запуску таймерів та cloud sync. |

| Пошкоджений профіль стратегії | Початкові байти синтаксично/семантично пошкодженого запису резервуються. Якщо backup не вдався, запис і очищення не дозволені. |
| Перезапис задач щосекунди | Незмінений масив зберігає посилання у annotateTaskChanges, тому звичайний tick не запускає збереження. |
| Різниця годинників | Допускається до 60 секунд випередження часу іншого пристрою; негативний проміжок не додається до обліку часу. |
| Очищення готових / відновлення | Перед перенесенням готових до історії потрібне підтвердження. Повернення з архіву зберігає done/completedAt; свідоме повернення в роботу лишається окремою дією. |
| Застаріла пропозиція і дати | Збережено локальну перевірку plannedDate/deadlineDate та полів розкладу. |
| «Так.» | Збережено локальне підтвердження актуальної пропозиції після явного питання про застосування; без зайвого запиту до Google. |

| Другорядні ШІ-запити | Спільна обмежена генерація з fallback; скасування breakdown/recommendations доходить через IPC і сервер до provider. Аудит підтримує скасування й повтор. |
| Облік використання | Спільний локальний журнал усіх функцій, повторних спроб моделей та непідтверджених результатів. Голосові сесії, перевірки ключа та voice token рахуються окремо. |

| Невдала стара міграція | Застосунок відкривається з recovery-попередженням; старе сховище зберігається. Новий workspace не перезаписується старими даними. |

| Вебключ у localStorage | Ключ перенесено в sessionStorage вкладки; постійний старий запис прибирається. Desktop використовує native secrets. |

## Пункти, які вже працювали до цього проходу

- Короткі кириличні тривалості «30 хв» / «2 год» у відповідях про можливості.
- Нейтральне «справ» не відкидається перевіркою роду.
- «Почати» для задачі без таймера записує стан початку роботи.
- Завершені архівні задачі враховуються в статистиці періоду. Окремий дефект «прогрес цілей падає» в поточному інтерфейсі не підтверджений; нового показника прогресу не додано.

## Межі й незавершене

- Підписання Windows-інсталятора потребує реального сертифіката та credentials; їх не надано. Підписання не налаштовано, інсталятор цього проходу не створювався.
- Новий sync-захист запобігає пошкодженим записам, але сам не ремонтує вже пошкоджені хмарні документи. Дані акаунтів під час роботи не читалися й не змінювалися.
- Локальний облік ШІ показує спостереження цього пристрою, а не залишок квоти Google або виклики з інших пристроїв.
- Журнал нотаток не ущільнюється автоматично: це зберігає конкурентні зміни. При нестачі місця збереження повертає видиму помилку.
- Аварійне завершення всього браузера без pagehide може лишити Google login до timeout; звичайне закриття вкладки має cancellation.
- Старі дані після невдалої legacy migration можуть потребувати окремого відновлення, якщо користувач уже створив новий workspace.
- Конфліктний або пошкоджений журнал перенесення вкладок не перезаписується автоматично; поточні дані та журнал залишаються доступними для відновлення.

## Перевірки

Виконано читання коду та повторний статичний перегляд субагентами. Додані регресійні сценарії для sync purge, конкурентних нотаток, пошкодженої стратегії, парного перенесення вкладок, невизначених відповідей, обліку ШІ, batch undo, часової різниці та login cancellation.

Тести, перевірка типів, збірки, живі UI/Google/Firebase сценарії та випуск **не запускалися**. Успішність нового коду виконанням не підтверджена. За AGENTS.md потрібен окремий явний дозвіл користувача на перевірки й окремо на випуск.

## Підготовка випуску — 15 жовтня 2026

Користувач окремо дозволив перевірки й випуск. Перший запуск знайшов три неузгоджені сценарії ШІ та помилки типів; їх виправлено. Публікація тоді не виконувалась. На сервері вже були релізи 1.3.9–1.3.10, тому правки перенесено в окремий release worktree на базі `5fcf8d4` (1.3.10), зі збереженням нового інтерфейсу й явного режиму знайомства. Незавершений архітектурний кандидат з іншої гілки до випуску не включено.

Додатково для інтерфейсу 1.3.10 виправлено прогрес цілей після очищення готових: завершений архів враховується з дедуплікацією. Явне зіставлення категорій під час зміни набору вкладок застосовується до задач, архіву й цілей. Очищення пам’яті також вимикає збережений явний режим знайомства.

Фактичні підсумки перевірок і публікації записуються у `visual-qa/release-1.3.11/VERIFICATION.md` та `publication.json`; попередні розділи описують стан до отримання дозволу.
