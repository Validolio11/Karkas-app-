# Karkas 1.3.1 — ізольована перевірка інтерфейсу

Дата: 12 жовтня 2026. Результат: **PASS**, шість груп сценаріїв. Перевірено фінальну production-збірку `http://127.0.0.1:54837`, bundle `app-hrG-eDiD.js`. Продуктовий код під час QA не змінювався.

Перевірка виконана в окремих Chromium-контекстах із синтетичними історіями, профілями та завданнями. Відповіді API підмінено; для знайомства використано справжній `sanitizeDiscoveryResponse`, для погодженого профілю — актуальний `confirmedProfile` із core test helpers. Реальних запитів до ШІ, приватного сервера 54736 чи встановленого застосунку не було.

## Перевірені сценарії

| Група | Результат і докази |
| --- | --- |
| Чат і меню | Desktop 1440×1000: чат 1100×950. Біла квадратна кнопка `+` 44×44, чорна іконка 16×16; розмір збігається з надсиланням. Вибір меню не надсилає запиту. Стрілки/Enter, Escape та натискання поза меню працюють. |
| Привітання та міграція | На акаунті без профілю привітання перше видиме; усі 36 старих повідомлень збережено після міграції guest history до v2. |
| Знайомство | Список бажань не заповнює перешкоди/ресурси/обставини/попередні спроби й не пропускає у чат передчасний план із довільного тексту моделі. Випадкове «так» не надає готовності. Навмисна непогоджена автономна відповідь не створює завдання. |
| Звичайні запити під час знайомства | Конкретна пропозиція завдання підтверджується «так» без додаткового API-запиту; чат залишається відкритим, знайомство не завершується. Після 11 звичайних розмов останнє питання відновлюється під час відкриття без генерації. |
| Підсумок і згода | Шість змістовних відповідей зберігаються; перед плануванням показано підсумок із цитатами. До згоди цілі не погоджені. Окреме «Так.» надсилає точний поточний `discoveryConfirmationId` і підтверджує лише цей підсумок. |
| Надсилання та відновлення | Ручний `@analysis` визначає намір; після повідомлення мітка зникає. Повтор після мережевої помилки зберігає turn ID та не дублює повідомлення. Чернетка відновлюється після перезавантаження без надсилання. Скасована затримана автономна відповідь не потрапляє в історію або завдання. |
| Автономна зміна та Undo | `expectedTask` використано з `request.taskSnapshots`; він дорівнює фактичному raw-завданню на момент запиту. Оновлення зберігає 75 секунд, виконаний і виміряний крок, currentStep. Undo повертає попередній заголовок і час. |
| Аналіз та конкурентна правка | Навмисний ready-план із actions у відповіді `@analysis` не змінює `latestStrategy` й не створює завдань. Затримане оновлення із застарілим snapshot не перезаписує синтетичну зміну пріоритету через справжній UI-handler; час також збережено. |
| Акаунти | Ключі пам’яті синтетичних A/B не змінено guest-сеансом; окремі v2 draft/history/welcome ключі акаунта з буквальним ID `guest` збережено. Незалежний браузерний контекст не отримує завдання або профіль іншого контексту. |
| Вигляд і помилки | Mobile 375×812: чат займає весь екран. Desktop/mobile чат і стратегія без горизонтального переповнення. Висота кнопки «Моя стратегія» дорівнює кнопці дашборда. Не зафіксовано необроблених помилок сторінки. |

Переглянуто сім знімків екрана. Знімок відновленого питання спочатку зроблено під час анімації відкриття; повторено лише його захоплення після завершення переходу, без повтору успішних сценаріїв або запитів ШІ.

## Межі перевірки

- Реальні переходи Firebase між авторизованими A/B у браузері не виконувалися. Перевірено структуру ключів/ізоляцію контекстів та статично переглянуто hydration, account, generation і profile-reference guards.
- Це перевірка клієнтської інтеграції, захистів і вигляду; якість реальної відповіді провайдера не оцінювалася.
- Windows packaging, повні тести та TypeScript виконує головний агент; цей звіт їх не дублює й не заявляє власного запуску.
